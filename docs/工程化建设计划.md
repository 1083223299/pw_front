#### 自动更新

- generic feed → `https://weilaidong.oss-cn-beijing.aliyuncs.com/pw-esports-front/`，`latest.yml` 驱动。
- 生命周期：启动检查 → **退出前检查**（`requestQuitWithUpdateCheck`）→ 下载 → `UpdateDialog.vue` 交互 → `quitAndInstall`。
- 平台差异：Win 检查失败显式提示；Mac 静默降级直接退出（`fa98a69`，因 `latest-mac.yml` 尚未发布）。

#### WebSocket 重连（`src/stores/notify.js`，最值得单独成文的一块）

| 机制 | 实现 |
|---|---|
| 地址 | `ws(s)://{host}/pws/admin/ws?token=...`，协议随页面自动切换（`buildWsUrl`） |
| 心跳 | `HEARTBEAT_INTERVAL = 25000`，OPEN 时发 `{"type":"PING"}`，收到 `PONG` 直接忽略 |
| 重连 | `delay = min(30000, 1000 × 2^reconnectAttempts)`；`onopen` 归零；`manualClosed` 让登出 / 切账号不再重连 |
| 幂等去重 | `offlineReplayDone`（本次登录只补弹一次）、`localStorage` 的 `notify:poppedIds` 去重（上限 200）、气泡上限 3、按通知 ID 合并列表项 |
| 消息契约 | `NOTIFICATION` / `UNREAD` 两类事件；`normalize()` 兼容多套历史字段命名 |
| 三层链路 | 开发：`vite.config.js` 的 `ws: true` 代理 → 打包：`localServer.js` 的 `server.on('upgrade')` 手工转发 `/pws/*`（含 `head` / `upstreamHead` 拼接）→ 后端 |
| 降级 | 未读数拉取失败不阻塞主界面，下次心跳 / 重连后自动补齐 |

#### 异常处理（分层现状）

| 层 | 现状 | 缺口 |
|---|---|---|
| 网络层 | `src/api/request.js` 响应拦截器：401 → 清 token → 跳登录 | 无统一超时 / 断网提示，无重试 |
| 业务层 | `src/api/api.js` 的 `requestData()`：`code === 0` 才算成功；`extractAxiosError` / `extractBusinessError` 双层错误提取，每个接口带 `fallback` 文案 | 错误码未分类，无统一错误码表 |
| UI 层 | 各页 `ElMessage.error(err.message)`，散落 | 无全局错误边界、无统一 loading / 空态 |
| 主进程 | `electron-log` 覆写 `console`（10MB 滚动，`main.log`）；`markLaunch()` 阶段日志；`uncaughtException` / `unhandledRejection` 记录；`render-process-gone` 自动 `reload()` | 只记录不上报、不弹提示；无崩溃恢复计数，存在无限重启风险 |
| 启动 | `whenReady().catch → 记录并 app.quit()` | 无用户可读的诊断页 |

## 5. L4｜联调方法论：吃透整条业务链路

### 5.1 三张必填表（每联调一个接口就更新）

- **接口契约表**：`路径 | 方法 | 入参(名称/类型/必填/校验) | 出参(字段/类型/可空) | code !== 0 的枚举 | 幂等键 | 超时 | 权限 | 关联页面`
- **权限矩阵表**：`角色/租户 | 可读接口 | 可写接口 | 数据范围 | 越权表现 | 前端是否已拦截`
  本项目已知：Bearer token 由 `request.js` 统一注入，401 清 token 并跳登录；租户余额类接口尤其要确认数据隔离范围。
- **数据流转表**：`触发方 → 接口 → 后端状态变更 → 回写字段 → 前端状态 → 下游依赖（WS 推送 / 角标 / 流水 / 对账）`

### 5.2 向后端提问清单

1. **契约**：字段命名以哪套为准（`notify.js` 的 `normalize()` 兼容了 `createdAt/created_at/timeText`、`orderId/order_id` 等多套，说明历史不统一）；uint64 ID 为什么前端要转 Number（`toApiId` 注释指向 Go 解析）；`code === 0` 之外还有哪些业务码。
2. **权限与租户**：token 有效期与刷新策略；租户维度如何隔离；401 之外是否有 403 / 412。
3. **状态机与幂等**：订单 / 流水状态枚举与合法流转；`/v1/tenant_balance/*` 加款是否幂等；WS 推送的 `NOTIFICATION` 是否与列表接口同源、会不会重复。
4. **异常与补偿**：支付未成功时「差额」仅作核对的口径归属；对账不平由谁发起冲正；WS 断线期间的消息靠 `listNotifications` 补还是后端重推。

### 5.3 一条链路的样例（可作为文档首页图）

```
订单创建 → 充值执行 → 财务流水(finance_list / finance_detail)
  → 实际充值金额 → 差额 / 总差额 → 租户余额扣减(tenant_balance/ledger 变动前/后余额)
  → 对账 → WS 通知(NOTIFICATION / UNREAD) → 托盘 / 角标 / 气泡
```

### 5.4 节奏

每次联调结束，当天更新三张表并在模块文档「接口契约」章节签字；看不懂的字段不猜，列入下次提问清单。

## 6. L5｜疑难问题知识库

### 6.1 条目模板

```markdown
# <一句话现象>
- 环境：OS / Electron / builder 版本 / 构建模式
- 现象：可复现步骤 + 报错原文（贴日志，不转述）
- 根因：定位到哪一层（前端 / 主进程 / 打包器 / OS / 后端）
- 定位过程：用了什么命令或工具，排除了哪些可能
- 解法：可直接复制的命令或代码 + 关联提交
- 预防：沉淀到哪个脚本 / CI 检查 / 规范
- 验证：怎么确认真的修好了
```

### 6.2 首批入库清单（按四域）

**Electron 打包报错**
- `release/win-unpacked` 被占用导致打包中断 → `check-release-lock.js` 主动清理 + `find-lock-owner.ps1` 定位占用进程（已工程化，写成完整案例）。
- `latest.yml` 的 SHA-512 与安装包不一致 → 发布前用 `openssl dgst -sha512 -binary … | base64` 校验（已实测通过）。
- Vite chunk > 500KB 警告；`after-pack.cjs` 只处理 Win（Mac 的 resources 路径是 `.app/Contents/Resources`，不能复用 Win 逻辑）。
- `predist` 钩子执行顺序、test / prod 环境变量的注入位置。

**跨平台兼容**
- Mac `hardenedRuntime: true` + `notarize: false` + 无 identity → Apple Silicon 提示「已损坏，无法打开」；自动更新强制要求签名。
- `safeStorage` 在 Mac 依赖 Keychain，签名身份不稳定时升级后可能解不开旧密文。
- Electron 的 `Notification` 的 `failed` 事件**仅 win32**，Mac 收不到，不能用来做通知权限检测。
- DMG 直开时登录项指向 `/Volumes` 临时路径 → `app.isInApplicationsFolder()` / `moveToApplicationsFolder()` 检测与引导（`fa98a69` 已实现）。
- `role: 'quit'` 绕过退出前更新检查 → 自定义 `Command+Q` 菜单项（已实现）；Dock 右键退出仍绕过，属有意保留（拦截 `before-quit` 会与 `quitAndInstall()` 打架）。
- 自绘标题栏与红黄绿按钮间距、`minWidth: 1100` 在 13 寸机型、深浅色切换、通知权限弹窗后的横幅行为 —— 待真机 QA。

**内存泄漏**
- `notify.js`：心跳 `setInterval`、重连 `setTimeout`、气泡 `setTimeout`、localStorage `poppedIds`（上限 200）、`bubbles`（上限 3）—— 核查登出 / 切账号时是否全部清理（`clearSocket` / `resetState` 已覆盖主路径）。
- ECharts 实例 `dispose()`、事件监听解绑、渲染进程 `reload` 后的重复注册、托盘闪烁 `stopTrayFlash()`、窗口关闭时的定时器清理。
- 排查手法：主进程 `process.memoryUsage()`、渲染进程 Performance Monitor、反复打开关闭详情抽屉对比 heap。

**大数据表格卡顿**
- `el-table` 全量 DOM 渲染、三大组件内同时挂载多个表格、xlsx 导出阻塞主线程、ECharts 与表格同页重绘。
- 方案候选：虚拟滚动、`row-key` 复用、分页 + 滚动加载、`manualChunks` 拆包、Web Worker 导出、筛选防抖。

### 6.3 沉淀规则

一坑一文档；必须带**复现步骤 + 报错原文 + 验证方式**；与修复提交互相链接；能自动化的一律沉淀进脚本或 CI，而不是只写文档。
